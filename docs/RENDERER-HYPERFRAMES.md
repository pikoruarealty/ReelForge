# Renderer: HyperFrames + GSAP

Branch `feat/hyperframes-gsap-renderer`. HyperFrames replaces Remotion as the default renderer (`RENDERER=remotion`
still selects the old one). **No extra paid API calls:** the same Claude, image and voice calls as before; all of the
improvement is in how the cached assets are turned into a video.

## Roles
| Tool | Role | Where |
|---|---|---|
| HyperFrames (Apache-2.0) | Renders HTML scenes frame-by-frame in headless Chrome + FFmpeg; lints (`check`) and snapshots frames | `packages/render-hf`, `hyperframes` dependency |
| GSAP 3.15 (free, all plugins) | All motion: every scene is one paused GSAP timeline. Bundled locally (`lib/gsap.min.js`), no CDN | scene scripts generated by `packages/render-hf/src/layouts.js` + `motion.js` |
| Blender MCP | Optional *offline* asset tool (3D phone/building turntables exported as PNG/MP4). Not part of the pipeline. | outputs go in `assets/3d/`, used as normal media |

## Pipeline
```
topic -> Claude idea/script (graphic.headline/highlight, 9-16 spoken words per scene) -> evaluate/revise
      -> images (2 paid by default / uploads) + narration (ElevenLabs | Kokoro | espeak | Windows speech)
      -> [render, no AI calls]  analyze narration (ffprobe + silencedetect)  -> timeline plan
                                 -> hf-project/ (index.html, s0..s5.html, captions.html, chrome.html)
                                 -> hyperframes check (fails on errors) -> hyperframes render -> reel.mp4
```
`apps/api/src/pipeline.js` -> `renderVideo()` / `renderHyperframes()`. The project is written to `storage/<job>/hf-project/`
and opens in HyperFrames Studio. `render-again` / `remix` / `regenerate` all reuse it, so they stay free.

## What changed vs the Remotion version (and why it looks better)
- **Audio-aligned scenes** (`timing.js`, `audio.js`): scene boundaries come from the voiceover (Whisper words if
  `ENABLE_WHISPER=true`, otherwise an estimate spread over the measured speech span). Video length follows the speech
  instead of a fixed 30 s / 3-4-5-6-6-6 split. Saved on the job as `job.timing`.
- **Karaoke captions** (`captions.js`): one captions composition, 3 words per group, active word highlighted, kept in
  the Reels/Shorts/TikTok-safe band.
- **Redesigned 9:16 layouts** (`layouts.js`): 7 families (hook, statement, device, stat, cards, ticker, endcard) behind
  the 18 existing creative-director layout names. Full-bleed photography with a slow camera move, large type in the
  safe zone, accent-word highlight, counters from real numbers in the copy. Frame 0 already shows the hook.
- **Motion vocabulary** (`motion.js`): 4 headline entrances picked per scene from the creative seed (mask, blur, slam,
  drop), 4 scene transitions with a visible cause (wipe with edge bar, iris, rise, push). No fade-and-slide everywhere.
- **Two paid images go further:** scenes without a real picture borrow the nearest real one with a different crop and
  camera move (never the same picture as the previous scene when avoidable); placeholder art is never shown full-frame.
- **Planner fix:** never two scenes of the same family back to back (`creative-director.js`); stat scenes without a number
  fall back to another family.
- **Lint gate:** `hyperframes check` runs before every render (safe zones, text overflow/overlap, occlusion, contrast,
  craft). Errors fail the job; warnings are counted in `job.hfCheck`.
- **Windows:** CLI is launched through `node`; demo narration uses the built-in Windows speech engine when `espeak` is absent.

## Config (`.env`)
`RENDERER=hyperframes|remotion`, `HYPERFRAMES_QUALITY=draft|standard|delivery`, `HYPERFRAMES_CHECK=true|false`,
`BACKGROUND_MUSIC=<file>` (optional, mixed at 13%). Requirements: Node 22+, FFmpeg, Chrome.

## Measured (this machine, Windows 11, GPU capture)
29.5 s Reel, 1080x1920, delivery quality: render ~51 s (+ ~30 s lint), 25 MB. Full demo job end to end: ~64 s.

## Known limits / next
- Word timing is an estimate unless Whisper is enabled; install `services/requirements-optional.txt` for exact captions.
- Quality still depends on the two paid images; upload property photos (`imageSource=uploaded`) for the best result.
- Remotion path is untouched but untested on Windows (needs `REMOTION_CHROME_EXECUTABLE`).
- Not done: music library, sound effects, registry blocks (`npx hyperframes add ...`), Blender-made 3D assets.

## Update: speech-driven motion and screenshots (feedback round 1)
Feedback from real runs: captions in the middle of the frame were distracting, pictures kept zooming for the whole line,
screenshots were cropped full-bleed, and nothing happened *while* the voice spoke. Changes:

- **Captions are off by default** (`CAPTION_MODE=impact`). Only a few *impact words* (numbers, the highlight word, key terms) are stamped
  on screen at the instant they are spoken (`beats.js`). `CAPTION_MODE=karaoke` restores word-by-word subtitles; `off` hides all.
- **No continuous zoom.** Pictures settle in once and hold still. A long photo scene gets one cut-in on a speech beat.
- **Motion lands on the voice.** Per scene, `beats.js` finds clause breaks and impact words from the word timings. The headline's accent word
  lights up when it is spoken; impact stamps pop when spoken; a screenshot camera steps on clause breaks.
- **Screenshots are shown whole.** Uploads are no longer cropped (previously `fit: cover` at upload *and* again in the pipeline).
  New per-job option `uploadFit`: `contain` (default, screenshots) or `cover` (photos, fills the frame). UI: toggle under "Upload my images".
  Scenes with an uploaded screenshot render as **PROOF**: the screenshot in a device frame, width-fit, with a camera that scrolls down it on
  clause breaks (a wide image is shown whole with one punch-in). Hook and number scenes stay text-only with the next screenshot rising
  from the bottom edge. Old uploads were already cropped to 9:16 and are shown as they are.
- **Visuals:** faint blueprint grid on brand backdrops, sticker-style stamps, device frame, ripple on clause breaks, scene rhythm alternates dark/cream.

## Hindi (voice and on-screen text)
Per-job option `language`: `en` (default), `hi` (Hindi voice + Hindi/Devanagari on-screen text) or `hi_voice` (Hindi voice, short English
on-screen text). UI: "Voice & on-screen language" above "Scene images".

- **Script:** Claude writes narration in conversational Hindi (Devanagari, numbers spelled as Hindi words so they are pronounced correctly)
  in the same single script call (`apps/api/src/language.js` holds the prompt clauses and word budgets). Revision and tightening passes keep the language.
- **Voice:** ElevenLabs `eleven_flash_v2_5` with `language_code: "hi"`. Premade voices speak Hindi with their own accent; your configured
  voice (a professional Indian voice) is blocked on the free plan (402), so the premade fallback is used until you upgrade.
- **Length:** measured 2.25 Hindi words/second including pauses (96 words = 42.6 s), so the budget is 62-70 words for ~30 s.
- **Fonts:** Inter has no Devanagari glyphs. Noto Sans Devanagari (SIL OFL, variable weight) ships in `packages/render-hf/assets/fonts/` and is
  declared in every scene whenever the script contains Devanagari. Devanagari headlines use taller lines, no negative letter-spacing, and a
  per-character width model so they fit (`devEm` in `layouts.js`).
- **Motion/timing:** the danda (।) ends a sentence for pacing, beats and caption groups. Hindi number words and units (लाख, करोड़, प्रतिशत) become
  impact stamps; Hindi stop-words never do. Labels (kickers, end card, city pills) have Hindi versions.
- **Demo mode:** has no Hindi voice unless the OS has one (espeak-ng `hi`, or a Windows hi-IN voice pack); otherwise narration is silent and
  `job.audioWarning` says so. Use live mode for real Hindi audio.
- **Whisper:** `ENABLE_WHISPER=true` uses a multilingual model for Hindi (`WHISPER_MODEL`, default `small`).
